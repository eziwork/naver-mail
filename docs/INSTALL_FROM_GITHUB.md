# GitHub 주소로 설치하는 방법

이 문서는 사용자가 저장소 주소를 주고 “이 플러그인을 설치해 줘”라고 요청했을 때 Codex 또는 로컬 MCP를 지원하는 데스크톱 Work가 따라야 할 설치 지침입니다. 사용자는 아래 두 줄만 전달하면 됩니다.

```text
https://github.com/eziwork/naver-mail
이 플러그인을 설치해 줘.
```

## 사용자가 보게 되는 흐름

1. 앱이 주소가 `https://github.com/eziwork/naver-mail`인지 확인하고 저장소의 최신 Release를 조회합니다.
2. 현재 OS와 CPU에 맞는 **운영 패키지**를 고릅니다. Windows x64는 `win32-x64.zip`, Intel Mac은 `darwin-x64.tar.gz`, Apple Silicon Mac은 `darwin-arm64.tar.gz`를 사용합니다.
3. 운영 패키지와 파일별 `.sha256` 또는 `SHA256SUMS.txt`를 받아 SHA-256 값이 일치하는지 확인합니다. 검사가 실패하면 압축을 풀거나 실행하지 않고 다운로드를 다시 시도하거나 사용자에게 원인을 알려 줍니다.
4. 앱이 관리하는 임시 폴더에 압축을 풀고 `.codex-plugin/plugin.json`, `.mcp.json`, `bin/`, `runtime/`, `dist/`가 모두 있는지 검사합니다. 검사가 끝난 완성 폴더만 개인·로컬 플러그인 목록에 등록합니다.
5. 기존 플러그인 항목과 계정 설정은 유지한 채 새 버전을 원자적으로 교체합니다. 중간에 실패하면 이전 설치를 그대로 사용하고 복구 방법을 표시합니다.
6. 설치 결과에 버전, OS·CPU, 체크섬 확인 여부, 설치 위치를 보여 주고 새 작업을 시작하도록 안내합니다. 네이버 비밀번호나 앱 비밀번호는 이 과정에서 요청하지 않습니다.

현재 공개된 최신 배포판은 `v0.2.0` 사전 배포판입니다. 정식 버전이 추가되면 안정 버전을 우선하고, 안정 버전이 없을 때만 사전 배포판을 선택한 뒤 그 상태를 사용자에게 표시합니다. Release의 **Source code**와 GitHub의 초록색 **Code → Download ZIP**은 실행 파일이 없는 개발 소스이므로 선택하지 않습니다.

## 호스트 구현 규칙

- 저장소의 README와 이 문서를 설치 지침으로 읽되, 저장소에서 임의의 설치 스크립트나 빌드 명령을 실행하지 않습니다.
- GitHub API 또는 Release 페이지에서 `draft`가 아닌 릴리스를 확인하고, OS·CPU가 일치하는 자산과 같은 이름의 체크섬 파일을 묶어 받습니다. 자산 이름·크기·SHA-256을 설치 결과에 기록합니다.
- 압축을 풀 위치는 앱이 관리하는 플러그인 설치 영역으로 제한합니다. 사용자의 홈·문서 폴더에 임의로 파일을 만들지 않고, 기존 플러그인 설정 파일을 덮어쓰지 않습니다.
- `.codex-plugin/plugin.json`의 이름·버전과 패키지의 `BUILD.json`을 서로 비교합니다. 버전이나 대상이 다르면 설치를 중단하고 새 Release를 선택합니다.
- `bin/naver-mail-bridge`(Windows는 `.exe`)가 실행 가능한지, `runtime/<platform>-<arch>/`에 동봉 Node가 있는지, 해당 OS의 키링 모듈과 `dist/worker.js`가 있는지 확인합니다. 사용자의 전역 Node·npm·Rust 설치를 전제로 하지 않습니다.
- 설치가 끝난 뒤 중계 초기화와 도구 목록 조회만 수행합니다. 네이버 계정 연결, 메일 조회, 발송은 사용자가 새 작업에서 별도로 요청할 때까지 수행하지 않습니다.
- 로그와 대화에는 로컬 경로·토큰·비밀번호를 필요 이상으로 남기지 않습니다. 다운로드·검사 실패 메시지는 네트워크, 체크섬, 권한, 실행 파일 누락 원인으로 구분합니다.

지원되지 않는 호스트에서는 [사용자 안내](USER_GUIDE.md)의 수동 절차로 전환합니다. 사용자가 Release 자산을 직접 내려받은 경우에도 같은 체크섬과 완성 폴더 검사를 거친 뒤 등록해야 합니다.

## 개발자·관리자 참고

이 저장소는 소스와 빌드 설정을 보관하는 원본입니다. `bin/`, `runtime/`, `dist/`, 운영용 `node_modules/`는 공개 Git 소스에 넣지 않고 Release 패키지에만 포함합니다. 따라서 `codex plugin marketplace add owner/repo`처럼 저장소 루트를 직접 마켓플레이스로 등록하는 방식은 이 프로젝트의 일반 사용자 설치 경로가 아닙니다. 로컬 마켓플레이스나 조직 배포 목록을 만들 때는 Release를 압축 해제한 **완성 플러그인 폴더**를 `source.path`가 가리키도록 구성합니다.

업데이트는 새 Release의 체크섬을 먼저 검증하고 임시 위치에서 전체 파일 검사를 끝낸 다음 한 번에 교체합니다. 교체 전 폴더를 보관하면 실행 오류가 발생했을 때 이전 버전으로 되돌릴 수 있습니다. 설치 작업이 중단되어도 네이버 계정의 OS 키링 레코드나 발송 준비 내용에는 접근하지 않습니다.
