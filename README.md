# 네이버 메일 · Eziwork

**Codex와 로컬 데스크톱 Work에서 내 네이버 메일을 찾고, 정리하고, 확인 후 보내는 플러그인입니다.**

“지난달 계약 관련 메일을 찾아 줘”, “이 메일에 답장을 써 줘”처럼 대화로 요청합니다. 메일 작업이 없으면 작은 Rust 중계 프로그램만 남고, Node 작업 프로세스는 자동으로 종료됩니다.

Eziwork가 만든 비공식 연결 도구이며 NAVER 공식 제품이 아닙니다. 내 컴퓨터에서 네이버 서버에 직접 연결합니다. 요청한 메일의 제목·본문 등은 요약과 답변을 위해 사용하는 AI 서비스에 전달될 수 있습니다.

## 이런 일을 할 수 있습니다

| 하고 싶은 일 | 대화 예시 |
| --- | --- |
| 최근 메일 확인 | “받은메일함의 최근 메일 20개를 보여 줘.” |
| 오래된 메일 검색 | “지난달 김대리에게 받은 계약 관련 메일을 찾아 줘.” |
| 여러 메일 정리 | “선택한 메일 세 개를 읽고 일정과 할 일을 정리해 줘.” |
| 첨부파일 저장 | “이 메일의 PDF 첨부파일을 다운로드해 줘.” |
| 답장 준비 | “답장을 작성하고 보내기 전에 전체 내용을 보여 줘.” |
| 읽음 상태 변경 | “이 메일을 읽음으로 표시해 줘.” |

본문을 조회하는 것만으로 네이버의 읽음 상태가 바뀌지 않습니다. 발송 전에는 보내는 주소, 받는 사람·참조·숨은 참조, 제목, 전체 본문, 첨부파일을 보여 줍니다. 그 내용을 본 뒤 **새 메시지에서 발송을 확인**해야 보냅니다.

## 설치: GitHub 주소 하나만 전달하세요

처음 사용하는 분은 아래 두 줄을 Codex 또는 로컬 MCP를 지원하는 데스크톱 Work에 그대로 붙여 넣으면 됩니다.

```text
https://github.com/eziwork/naver-mail
이 플러그인을 설치해 줘.
```

지원되는 호스트는 저장소의 최신 **Release**에서 현재 운영체제·CPU에 맞는 운영 패키지를 선택하고, `SHA256SUMS.txt` 또는 파일별 `.sha256`으로 검증한 뒤, 압축을 풀어 로컬 플러그인으로 등록합니다. 이 패키지에는 실행 파일·고정 Node 런타임·OS별 키링 모듈이 함께 있으므로 사용자가 Node, npm, Rust, 터미널을 설치하거나 실행할 필요가 없습니다. 설치가 끝나면 새 작업에서 **“네이버 메일 연결해 줘”**라고 입력하세요.

호스트가 GitHub 주소 설치를 지원하지 않는 경우에만 [설치와 첫 연결 안내](docs/USER_GUIDE.md)의 수동 대체 절차를 사용하세요. 초록색 **Code → Download ZIP**과 Releases의 **Source code**는 개발용 원본이며, 일반 설치에는 실행 파일과 런타임이 들어 있는 운영 패키지를 사용해야 합니다. GitHub에 코드를 공개하는 것과 OpenAI의 공식 플러그인 목록에 등록하는 것은 별도 절차입니다. Codex가 이 주소를 설치할 때 따라야 할 검사 순서는 [GitHub 주소 설치 지침](docs/INSTALL_FROM_GITHUB.md)에 정리되어 있습니다.

![네이버 보안 설정과 다음 단계를 안내하는 연결 첫 화면](docs/images/setup-start.png)

비밀번호는 열린 로컬 연결 화면에서만 입력합니다. 네이버 로그인 비밀번호나 앱 비밀번호를 대화에 붙여 넣지 마세요. 화면 이미지는 가상 계정으로 촬영했습니다.

## 지원 범위와 현재 배포 상태

**0.2.0은 사전 배포판입니다.** Windows에서 실행과 네이버 인증을 검증했습니다. Mac용 패키지도 제공하지만 실제 Mac 앱 연결·키체인·첨부파일 보호 검증과 코드서명·공증은 남아 있습니다.

| 환경 | 상태 |
| --- | --- |
| Windows x64 | 로컬 실행·동시 연결·유휴 종료·실제 IMAP/SMTP 인증 검증 |
| macOS Intel | 패키지 및 실행 파일 제공, 실제 기기 검증 필요 |
| macOS Apple Silicon | 패키지 및 실행 파일 제공, 실제 기기 검증 필요 |
| Codex / 로컬 MCP를 실행하는 데스크톱 Work | 대상 환경. 호스트 앱의 로컬 MCP 지원·조직 정책에 따름 |
| 웹·클라우드 Work / 모바일 | 이번 버전의 지원 범위에 포함하지 않음 |

한 번에 네이버 계정 하나를 연결하며, 사용자가 요청했을 때만 조회·발송합니다. 새 메일 상시 감시, 예약 발송, 메일 삭제·이동은 제공하지 않습니다. 실제 발송 검증 여부와 최신 CI 결과는 [배포 상태](RELEASE.md)를 확인하세요.

## 대기 메모리는 어떻게 줄였나요?

앱이 메일 기능을 불러오면 Rust 중계가 도구 목록과 연결 유지 요청을 처리합니다. 실제 도구를 호출할 때만 Node를 실행합니다. 작업이 끝나고 **30초 동안 사용하지 않으면 Node가 종료**됩니다. 다음 요청에서는 다시 시작합니다.

| Windows 측정 항목 | 결과 |
| --- | --- |
| 이전 버전 대기 메모리 | 약 95 MiB |
| 0.2.0 최대 대기 메모리 | **7.56 MiB** |
| 30초 유휴 후 Node 프로세스 | **0개** |
| Node 준비 시간 | **0.921~1.305초** |

MCP 연결 1개에서 실제 30초 유휴를 5회 반복한 작업 집합 기준입니다. 네이버 통신 시간은 제외했습니다. 설정 화면, 진행 중인 요청, 유효한 발송 초안이 있으면 Node를 유지하므로 메모리가 더 큽니다. 여러 연결의 Rust 중계 메모리는 합산해야 합니다. [원본 측정값](docs/measurements/windows-0.2.0.json)과 [설계 설명](docs/ARCHITECTURE.md)을 제공합니다.

## 계정과 메일은 어디에 저장되나요?

- 앱 비밀번호: Windows 자격 증명 관리자 또는 macOS 키체인. 평문 파일로 대체 저장하지 않습니다.
- 발송 준비 내용: Node 메모리에 최대 10분. 발송·만료·계정 변경·프로세스 종료 시 사용할 수 없게 됩니다.
- 요청한 첨부파일: 사용자 다운로드 폴더의 `Naver Mail Attachments`.
- 선택한 메일 정보: 요청한 작업을 위해 Codex/Work에 반환되며 대화 기록에는 호스트 서비스의 보관 정책이 적용됩니다.

Eziwork의 메일 수집 서버, 원격 분석, 사용량 추적 기능은 없습니다. “네이버 메일 연결 해제해 줘”라고 요청하면 이 컴퓨터의 저장된 연결 정보가 삭제됩니다. 네이버에서도 해당 앱 비밀번호를 삭제하면 네이버 측 접근 권한을 폐기할 수 있습니다.
